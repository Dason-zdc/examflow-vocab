## 1. 产品概述

### 1.1 一句话定位

面向**中国大陆雅思（IELTS Academic）考生**的应试背单词 Web 应用（PWA）：**以公开词汇表的学术权重决定学什么，以考试日期决定什么时候复习，以键盘/触屏双模交互保证效率。**

### 1.2 首发范围

| 项 | 决策 | 依据 |
| :-- | :-- | :-- |
| 首发考试 | **IELTS Academic（学术类）—— 书面定稿，Q-01 已关闭** | 学术类词汇边界可由公开学术词表（AWL）界定，无需真题语料即可建立可辩护的优先级 |
| 首发词量 | **2,000 lemma 级**（约 2,600~3,000 张义项卡） | 覆盖 AWL 570 家族展开 + Oxford 5000 中 B2–C1 学术层，扣掉 Oxford 3000 基础词 |
| **MVP 只发布 IELTS 一个数据包** | `ExamCode` 枚举**保留全部取值**（`'IELTS' \| 'CET4' \| 'CET6' \| 'KAOYAN' \| 'TOEFL'`），数据结构与调度逻辑按多考试设计；但 MVP 只构建、只分发、只装载 `IELTS` 包 | 枚举保留是为了避免后续加包时改数据模型，**不代表 MVP 要实现对多考试的 UI 切换** |
| 考研（KAOYAN）的定位 | **降为后续数据包**，归入 S-05 候选（与 CET-6 并列），按 M1 用户反馈决定先后顺序 | v0.2 曾以考研为首发假设，v0.3 已整体切换 |
| 首发平台 | 桌面浏览器：**Chrome 111+ / Edge 111+ / Safari 16.4+ / Firefox 128+**；移动浏览器：**iOS Safari 16.4+、Android Chrome 111+**（均覆盖最新两个大版本） | **下限由 Tailwind v4 硬性要求决定，低于该版本为「核心功能不可用」，不是样式降级**，理由见 8.3 |
| 不在首发内 | IELTS General Training、听力场景词专项、口语/写作批改 | 见 1.4 非目标 |

### 1.3 要解决的问题（问题陈述）

中国大陆雅思考生在**词汇环节**的真实困境，按优先级排序：

| 优先级 | 痛点 | 现状怎么解决 | 为什么不行 | 支撑来源 |
| :-- | :-- | :-- | :-- | :-- |
| **P1** | **学了考不到 / 认识但用不出**：词书按字母序或泛泛词频排序，读得懂词表、读不懂阅读里的同义替换（雅思阅读约 60% 的题目考查 paraphrase） | 背《雅思词汇红宝书》/《王陆 807》/ App 自带“雅思核心词” | 词表“拎不清取舍”：同时收录 sedentary/calf/syrup 等极低分词和 check/business/fruit 等超简单词；且只标中文释义，不标搭配与同义替换，背完仍“认识但不会用” | [新航道：雅思词汇书五大弊端](https://bj.xhd.cn/ielts/ieltsxx/113023.html)；[有考网：红宝书短板](https://m.yongkao.com/waiyu/ielts/150686.html)；[勤学：雅思阅读 60% 题考同义替换](https://m.qinxue365.com/yyxx/ieltszx/251341.html) |
| **P2** | **熟词僻义 + 形近词混淆**：认识 address=地址，阅读考的是「处理、解决」；adapt / adopt / adept 分不清 | 靠真题里的个人生词本手工整理 | 手工成本极高且无复习调度，整理完就忘 | 同上；[今日头条：雅思词汇避坑指南](https://www.toutiao.com/a7671467884752683561) |
| **P3** | **复习节奏与考期脱节**：通用间隔重复把复习排到考试之后 | Anki / 墨墨 / 不背单词均为通用 SRS，无考试倒计时感知 | **主流 App 全部不具备“考试期倒排”能力**（见第 3 章：无一个竞品有考期感知调度） | 竞品矩阵第 3 章 |
| **P4** | **停一天就“单词高利贷”**：中断后复习量雪崩，直接弃坑 | 不背单词被用户戏称“单词高利贷”，用户公开喊话官方出“暂停复习” | 无积压治理与“考前收缩”机制 | [什么值得买：三类 App 收费逻辑与三个坑](https://post.m.smzdm.com/p/avgwlvpn/) |
| **P5** | **付费墙 / 单词上限焦虑**：墨墨按“加入记忆计划的单词总数”计费，新注册仅约 602 词额度 | 签到攒上限或付费（有用户晒单 163 元买 17,600 词上限） | 已背熟的老词仍占额度；心理成本高于金钱成本 | [同上](https://post.m.smzdm.com/p/avgwlvpn/)；[1920m：墨墨优缺点](https://www.1920m.com/sites/maimemo.html) |
| **P6** | **跨端割裂**：图书馆/机房要全键盘，通勤要单手 | 用 App（移动端好、桌面端无）+ 网页版凑合 | 主流背单词产品均为 App 优先，Web 端功能残缺，**键盘优先的学术刷词工具基本空白** | [ieltsbiz：2026 雅思词汇工具测评](https://ieltsbiz.com/blog/best-ielts-vocabulary-apps) |

### 1.4 非目标（本期明确不做）

- IELTS **General Training** 数据包（v0.3 新增，D-09）。
- 听力、口语、写作批改、模考。
- 社交、打卡排行、付费体系（商业模式另行立项）。
- 多设备云同步（P2 / C-01）。
- 原生 App（仅 PWA）。
- **运行时 AI 任何形态**（Q-05 定稿：MVP 不含 AI；“构建期离线标注”是数据工程手段，不属于运行时 AI，见 9.4）。
- 商业授权词典内容与有道等第三方非公开接口。

### 1.5 设计红线（【禁止】P0 绝对规则，团队级）

| 规则 | 在本 PRD 中的落地约束 |
| :-- | :-- |
| 禁止 emoji 作为功能图标 | 所有功能图标一律使用**统一 SVG 图标库**（单一 sprite 或多组件 id 一致的模块），由架构师按项目选型锁定，PM 不预设具体库。文案中描述图标一律用文字语义，如「发音喇叭图标」「展开箭头图标」「书签图标」 |
| 禁止紫色→粉色渐变 | 视觉方案不含紫→粉渐变。交互侧参考色板（可由设计师调整）：主操作色建议走**靛蓝/晴蓝系**，强调色走**琥珀/翠绿系**，中性走**石板灰**（与演示原型现有基调一致），所有渐变必须为非紫-粉方向的低饱和渐变或纯色 |
| 禁止 AI 模板味文案 | 全文不出现 “Welcome to” / “Lorem ipsum” / “赋能” / “一站式” 等空洞占位。所有界面文案由本 PRD 的 5.2/5.3/5.6 节指定，空状态、错误态、加载态文案见第 12 章 |

### 2.2 次要画像 P1：在职 / 转岗需求者（约占 20%）

- 25–32 岁，职场人；“内地求职”已是雅思报考**第二大动因**，超 55% 职场人在求职/晋升/对接海外业务时被要求提供雅思成绩（[BC 报告解读](https://www.becvip.com/News_read_id_2757.shtml)）。
- 每日可投入 1–1.5 小时，碎片化；强依赖通勤场景与离线可用。
- 对“会不会考前背不完”的焦虑最强 → **每日计划的可视化承诺是本产品对他最强钩子**。

### 2.3 非目标画像

- IELTS General Training 考生、移民类、**低起点（低于 A2 / 词汇量 < 3,500）者**——MVP 的学习曲线与词表均不匹配。
- K12 / 国内考研 / CET（留给后续数据包，见 S-05）。

### 3.1 直接竞品矩阵（中文主流背单词 App）

| 竞品 | IELTS 词书做法 | 核心功能 | 优势 | **劣势（来自差评/测评）** | 定价（含来源） |

> **实现说明（2026-10-22，ADR-006）**：`synonyms` 字段已细化为义项级 `sense.synonymGroups[]`——
> 按 WordNet synset 分组，每组带英文释义与搭配框架，候选分「可替换 / 框架一致 / 需改写 / 搭配不符 / 待验证」五态。

> 「该分区显示一行说明」——形近词与同义替换同处一个可折叠区块，整块隐藏会连带藏掉形近词。
> 用户价值（阅读中把替换词对上）不变；PRD 示例 `increase → surge/escalate` 仍不产出，登记为 G-5。

> **范围边界**：US-08 仅做「展示」，**不新增「同义替换练习模式」「同义替换卡型」**，实现成本落在 M-01 数据包字段与详情页 UI 内。

### 5.1 数据来源与授权

| 数据 | 来源 | 授权 | 在 MVP 中的用法 |
| :-- | :-- | :-- | :-- |
| 词条、音标、中文释义、词形变化 | ECDICT（skywind3000/ECDICT） | MIT | 基础词典 + `lemma-map` 变形还原 |

### 5.3 「义项考频」的诚实定义（Q-03/Q-04 落地答案）

**没有真题语料，就不许说「在雅思中出现 22 次」。** 因此：

1. `Sense.examStats.IELTS.freq` 更名为 **`senseWeight`（0–100 的合成权重）**，并携带 `kind: 'ESTIMATED'`。
2. 合成公式【估算，M0 用真实数据校准】：

\[
senseWeight = 100 \times \left(0.45\,W_{awl} + 0.30\,W_{gen} + 0.15\,W_{ox} + 0.10\,W_{wn}\right)
\]

| 分量 | 取值规则 |
| :-- | :-- |
| \(W_{awl}\) | AWL Sublist 1–3 → 1.0；Sublist 4–6 → 0.7；Sublist 7–10 → 0.4；非 AWL → 0.2 |
| \(W_{gen}\) | 公开通用词频表百分位：**用在时态的中间段赋最高值**（排除超高频基础词与极低频生僻词），归一化到 0–1 |
| \(W_{ox}\) | Oxford 5000 内 B2–C1 且非 Oxford 3000 → 1.0，其余 0 |
| \(W_{wn}\) | WordNet 该 lemma 下该 sense 的语料频次占比，归一化到 0–1 |

3. **分层（替代 v0.2 的「前 30% 卡片」这种不可解释的定义）**：

| Tier | 判定 | 卡片标注 | 名额（目标） |
| :-- | :-- | :-- | :-- |
| 核心 | AWL Sublist 1–3，或 senseWeight ≥ 75 | 核心卡 | ~30% |
| 进阶 | senseWeight 50–75 | 进阶卡 | ~40% |
| 拓展 | 其余 | 拓展卡 | ~30% |

4. **UI 必须明示**（不可省略文案，见 12.3）：
   > 「义项权重依据公开学术词表（AWL）、通用语料词频与词典义项频次合成，为**估计值**，非雅思真题出现次数。」

5. **熟词僻义判定**（改写自 v0.2 4.2④，去掉真题依赖）：满足**全部**条件 → 标为熟词僻义【估算阈值，M0 校准】
   - 该义项**不是** Oxford 3000 词义中的首义（基础义）；且
   - 该义项在同 lemma 内 `senseWeight` 排名非第一，但 ≥ 40；或 WordNet 频次占比 ≥ 15%。

6. **北极星指标中的「核心卡片」** 改定义为：**Tier = 核心 的卡片**（不再用百分位），保证用户能理解「我在冲哪批词」。

### 5.4 仿真例句规范（Q-02 定稿 B）

| 项 | 规则 |
| :-- | :-- |
| 数量 | 每张卡 ≥ 1 条；每个义项至少覆盖 1 条 |
| 场景 | 雅思阅读常见学术题材（环境、健康、教育、科技、社会、历史、能源、交通），句式模仿学术英语，**不引用任何真题原句或近原句改写** |
| 长度 | 句中生词密度 ≤ 1 个，避免 v0.2/纸质书被批评的「一个例句 3–4 个生词」问题 |
| 标注 | 数据结构 `provenance: { type: 'ADAPTED', note: '仿真例句，非考试真题' }`；UI 上以「仿真例句」小标签显示 |
| 禁止 | 出现真实年份 + 试卷编号 + 篇章名的组合（会构成“疑似真题”暗示） |

### 5.5 形近词与词根

- 候选生成范围限定在「IELTS 包 + Oxford 3000」，避免全库 O(n²)。
- 三类触发：`SPELLING`（编辑距离 ≤ 2 且长度差 ≤ 2）、`SOUND`（Double Metaphone 同码）、`ROOT`（共享词根）。
- 每词最多保留 3 个，`tip` 为人工书写的区分要点，编辑全量审阅前 2,000 lemma。
- 词根 `etymology` 依据公开词源资料自行撰写，**不复制任何词典的词源正文**。

### 5.6 质量验收

| 项 | 验收标准【估算】 | 方法 |
| :-- | :-- | :-- |
| 义项筛选准确率（前 500 lemma） | ≥ 95% | 随机抽样 300 条由第二人盲审 |
| 义项筛选准确率（其余） | ≥ 90% | 随机抽样 300 条 |
| 熟词僻义标记准确性 | ≥ 90% | 抽样 200 个标记由 IELTS 教研复核 |
| 形近词 tip 无事实错误 | 100% | 编辑全量审阅前 2,000 lemma |
| 例句与义项匹配率 | 100% | 脚本校验 `senseId` 关联 + 抽样 200 条人工 |
| 例句 ADAPTED 标注率 | 100% | 脚本校验 |
| 例句生词密度 | ≤ 1 个/句 | 脚本对「IELTS 包 ∪ Oxford 3000」外 token 计数 |
| lemma 还原映射覆盖率 | ≥ 98%（抽样 500 token） | 人工核对 |

### 5.7 发布与版本

- 每个考试数据包 = `/packs/IELTS/manifest.json` + `chunk-{n}.json`（每块约 500 lemma）+ `lemma-map.json`。
- MVP 目标 **2,000 lemma ≈ 4 个 chunk**，首块随应用发布，其余按需下载并缓存到 IndexedDB。
- 按 sha256 校验，失败重试且不落盘；`wordId` / `senseId` 一经发布永不复用。
- **合规提示（务必让法务过一遍）**：Oxford 3000/5000 与 AWL 的词 membership 判定在工程上属于「事实性清单引用」，风险较低；但**任何形式的整表再分发、或其出版物体例/释义/例句的搬运都不允许**。建议在「关于」页列出全部来源与原始出处链接，并注明「本产品不隶属于、也未获得 Oxford University Press 或 Victoria University of Wellington 的背书」。

### 6.4 学习卡片流程

```text
┌──────────────┐  Space 揭示 / 1·2·3 预判   ┌──────────────┐  Space/→ 下一个   ┌────────────┐
│ 正面：回忆   │ ─────────────────────────→ │ 背面：复盘   │ ────────────────→ │ 提交评分   │
│ 单词+音标+例句│                            │ 释义/例句/词根│                   │ 进入下一卡 │
└──────────────┘                            └──────────────┘                   └────────────┘
```

1. **正面**：单词、音标、与该卡义项匹配的**英文仿真例句**（不显示中文）。熟词僻义卡额外提示「本句中的含义？」。
2. **揭示**：Space 直接揭示（未预判），揭示后必须选 1 不认识 / 2 模糊 / 3 认识；或按 1/2/3 预判并揭示。
3. **背面**：该义项的**权重条与 Tier 徽章 + 估计值说明**、例句与译文、词根（R）、形近词与同义替换（F）、笔记；当前卡对应义项高亮。
4. **修正**：预判「认识」后，背面按 1 = 「记错了」（改为不认识），按 2 = 改为模糊。
5. **提交时机**：评分在**离开卡片时**一次性提交；离开前的修改只改待提交值，不会重复调度。
6. **撤销**：Z 撤销最近一次提交（恢复 FSRS 状态、删除对应 reviewLog、卡片回到当前位置）。
7. **斩词**：X 将该词全部卡片标为「已掌握」（暂停调度），词库页可恢复；可撤销。

### 6.5 每日计划

沿用 v0.2 5.3 全部公式，仅两点调整：

- **日切**：本地时间 04:00（可设置）。
- \(N\) 定义为「IELTS 包中 Tier ∈ {核心, 进阶} 且未学习、未斩词的卡片数」，默认不含「拓展」层，避免用户被低价值词占满配额。用户可在设置中打开「含拓展层」。
- 过轮窗口 \(B\)：默认 7；\(D \le 21\) 时 \(B = \max(1, \lfloor D/3 \rfloor)\)。
- 复习优先级 = 层级权重 × \((1 - R_{now})\)，层级权重：**核心 1.0 / 进阶 0.7 / 拓展 0.4**（对应 Tier，替换 v0.2 的“核心 = 前 30%”）。
- 积压 > 2 天在首页提示并建议当日暂停新卡。

### 6.7 调度引擎（宏观层）

- 选型：**ts-fsrs**，锁定具体版本，升级需回放回归；默认参数用内置默认值。
- **卡片粒度**：每 lemma 1 张主义项卡（`senseWeight` 最高者）；每个熟词僻义义项 1 张僻义卡；**每 lemma 最多 3 张卡**。
- **兄弟卡错开**：同一 lemma 的多张卡，同一天内最多出现 1 张；新卡阶段主义项卡先学。
- **评分映射**：不认识/记错了 → Again；模糊 → Hard；认识 → Good；斩词 → 不调用调度，标记已掌握。**不提供 Easy**（Q-07 定稿）。
- **每日首评**：每卡每学习日只有首评进入 ts-fsrs；同日后续重现仅影响日内队列，并以 `sessionOnly = true` 写日志。
- **考期适配**：
  - 间隔上限 \(I_{final} = \min(I_{fsrs}, \max(1, D-1))\)。
  - 目标留存率【估算，M1 校准】：\(D > 30\) → 0.90；\(8 \le D \le 30\) → 0.93；\(D \le 7\) → 0.95。
  - 考前过轮：进入 \(D \le B\) 时，将「核心卡中预测考试日 \(R < 0.9\) 且窗口内无到期安排」的卡均匀分配到窗口各天。

### 6.8 日内重现队列（微观层）

沿用 v0.2 5.6：出现即为深切不变；「不认识」积分置 0、「模糊」置 1、被打回后「认识」+1，积分 ≥ 2 通关。重新插入需同时满足「之后至少隔 3 张卡」与「距本次至少 60 秒」【估算】，取更靠后者；不足则该卡标为「待巩固」。

### 6.9 发音

- 默认浏览器 Web Speech（en-GB / en-US）；无可用语音时**隐藏发音按钮并在设置页给出说明**（不显示不可点的死按钮）。
- 自动播放可在设置中关闭。
- P1 评估预生成音频；不依赖第三方非公开接口。

## 8. 指标体系

### 8.1 北极星指标

**考试日预测掌握的核心考点数**：考试当天，预测回忆概率 \(R \ge 0.9\) 的**核心卡（Tier = CORE）**数量。

- 计算：对每张核心卡，用 FSRS 以「考试日 − 上次复习日」为间隔算 \(R\)，统计 \(R \ge 0.9\) 的数量；同时报告占核心卡总数比例（**核心覆盖率**）。
- 全部在本地计算，在首页与（P1）仪表盘展示。
- **改定义理由**：v0.2 的「义项考频前 30%」在 IELTS 合成权重下不可解释；改为 Tier = CORE，用户能明确知道自己在冲哪批词。

### 8.2 过程指标

| 指标 | 定义 | 初始目标【估算】 |
| :-- | :-- | :-- |
| 每日计划完成率 | 当日完成的计划新卡 + 到期复习卡 ÷ 当日计划总数 | ≥ 70% |
| 7 日留存 | 首次使用后第 7 天（±1 天）仍完成过一次学习的用户占比 | ≥ 35% |
| 复习回忆率 | 到期复习卡中首评非 Again 的比例 | 0.85 ~ 0.92（过高说明间隔太保守） |
| 积压天数 | 当前积压到期卡 ÷ 每日复习上限 | ≤ 2 天 |
| 核心覆盖率（考试日） | 见 8.1 | ≥ 80%（目标总分 6.5 的主要画像） |

### 8.3 非功能指标

| 指标 | 定义 | 目标 |
| :-- | :-- | :-- |
| 交互响应 | 按键/点击到下一帧渲染完成（P95，中端安卓机） | ≤ 50 ms |
| 首屏可交互 | 已缓存数据包时，冷启动到首张卡可操作（P95） | ≤ 2 s |
| 离线可用 | 首次加载完成后断网，学习/复习/备份可用 | 100% |
| 数据包体积 | 2,000 lemma 全包（含例句/词根/形近词） | ≤ 6 MB（分块压缩后）【估算】 |
| **浏览器支持下限** | 桌面 Chrome 111+ / Edge 111+ / Safari 16.4+ / Firefox 128+；移动 iOS Safari 16.4+ / Android Chrome 111+ | **低于该下限视为核心功能不可用（不受支持的浏览器需显示升级引导页），而非“样式略有降级”** |

**浏览器下限的设定理由（为什么不是「最新两个大版本」这种模糊表述）**：

MVP 技术栈使用 **Tailwind CSS v4**，它依赖的现代 CSS 特性决定了硬性下限，低于该版本的浏览器上**卡片渲染、布局与主题变量会失效**，属于核心功能不可用，不是渐进增强问题。因此：

| 浏览器 | 下限 | 由 Tailwind v4 的哪项要求决定 |
| :-- | :-- | :-- |
| Safari（含 iOS） | **16.4+** | `@property`（自定义属性注册）16.4 起支持；`color-mix()` 也需 16.2+ |
| Chrome / Edge | **111+** | `@property` 111 起支持；`color-mix()` 111 起支持 |
| Firefox | **128+** | `@property` 与 `color-mix()` 均需 128+ |

执行要求：

1. 应用启动时做一次能力检测（`@supports (background: color-mix(in oklab, red, blue))` + `@property` 注册探测），**不支持则渲染「请升级浏览器」引导页，不渲染学习主界面**。
2. 该引导页需给出明确的版本号文案：「本应用需要 Chrome 111 及以上 / Safari 16.4 及以上 / Firefox 128 及以上。」
3. 此检测属 P0（M-09 的一部分），不能留到 P1。

### 8.4 数据采集与埋点方案

- **MVP 默认不上传任何数据**，所有指标在本地计算与展示。
- 匿名统计开关（Q-06 定稿）：**默认关闭，且 MVP 周期内不上线开关 UI**；仅预留数据契约。
- **MVP 必须实现的本地埋点（不上传，仅用于本地清单校验与 M1 导出分析）**：

| 事件类别 | 事件名 | 何时触发 | 关键属性 |
| :-- | :-- | :-- | :-- |
| 激活 | `first_card_reviewed` | 用户完成第一张卡的评分提交 | card_id, tier, card_kind |
| 学习 | `card_committed` | 每次评分提交 | card_id, rating, prejudged, corrected, duration_ms, D（距考天数） |
| 计划 | `daily_plan_generated` | 每日首次进入学习页 | n_new, due_count, backlog_days, core_coverage_est |
| 留存 | `session_start` / `session_end` | 一轮学习开始/结束 | cards_in_round, duration_ms |
| 异常 | `error_occurred` | 前端异常 / API 错误 | message, stack_hash, route |
| 备份 | `backup_exported` / `backup_imported` | 导出/导入成功 | entity_counts |

- 命名规范：`{对象}_{动作}`；属性附带 `timestamp`、`device`、`app_version`。**不采集任何用户输入内容（笔记、例句内容）与 IP。**

## 10. 边界条件

| 场景 | 期望行为 |
| :-- | :-- |
| **空状态** | ①未设置考试日期：首页显示「设置考试日期」主 CTA，不生成每日计划；②当日无到期卡：显示「今天没有到期复习，可以开始新一轮」；③词包下载失败：显示重试 + 明确错误原因，不留白屏 |
| **错误状态** | 数据包 sha256 校验失败→不落盘并提示；导入文件 `formatVersion` 高于客户端→拒绝并提示升级；IndexedDB 不可用（隐私模式）→降级提示并阻断首次进入，明确告知无法保存进度 |
| **加载状态** | 首块数据加载骨架屏（≤ 2s）；分块下载显示进度条，可中断续传 |
| **边界值** | 考试日期 = 今天（D=0）或已过期；D=1；maxNewPerDay = 0；用户把日切设为 23:00 |
| **过期处理** | 考试日期过后，提示设置新考试日期或切换「长期记忆模式」（取消考期截断，留存率恢复 0.9） |
| **并发** | 同一用户多标签页打开：后一个标签页检测到写冲突时提示「检测到另一个标签页正在学习，请只保留一个」 |
| **离线** | 断网后学习/复习/导出/导入全部可用；仅分块下载不可用并显示离线提示 |
| **权限拒绝** | Web Speech 无可用语音 → 隐藏发音按钮 + 设置页说明；`storage.persist()` 被拒 → 设置页显示「添加到主屏幕」引导 |
| **异常数据** | 用户直接导入他人的备份文件 → 按 `schemaVersion` 校验，格式不符给出明确报错文案（见 12.3） |

## 12. 文案与交互红线

### 12.1 禁止项

- emoji 充当功能图标（用统一 SVG 图标库）。
- 紫色→粉色渐变。
- "Welcome to" / "Lorem ipsum" / "赋能" / "一站式" / "让学习更简单" 类空洞文案。

### 12.2 允许的方向（具体文案可微调）

| 位置 | 文案 |
| :-- | :-- |
| 首页主标题（未设考期） | 「离雅思还有多久？设定考试日期，我帮你算每天该背多少。」 |
| 首页每日计划条 | 「今天：新词 50 · 复习 132 · 预计 38 分钟」 |
| 无法学完提示 | 「按每天 50 个新词，考前只能覆盖 62% 的核心词。可以提高上限，或只冲最高频的 800 个义项。」 |
| 无到期卡 | 「今天没有到期要复习的词。开始新一轮？」 |
| 本轮结束小结 | 「本轮完成：学习 50 · 通关 34 · 待巩固 6」 |

### 12.3 必须出现的合规/可解释文案

- 义项权重旁：**「依据公开学术词表（AWL）与通用词频合成，为估计值，非真题出现次数。」**
- 每张仿真例句旁：**「仿真例句」** 小标签。
- 关于页：全部数据来源与许可声明 + 「本产品不隶属于、也未获得 Oxford University Press 或 Victoria University of Wellington 的背书」。
- 备份失败/版本不符：「无法导入：备份文件版本高于当前应用版本，请更新后再试。」

### 12.4 考频口径的 UI 措辞规范（**合规红线，落到文案层**）

> **事实前提**：MVP 的义项考频来自 **ECDICT + WordNet + 公开词频（Oxford 3000/5000、AWL 学术词表）**，是**公开语料的近似值**，**不是历年雅思真题语料的统计结果**。
> **因此：产品内任何出现「考频 / 出现 N 次 / 高频」的位置，都必须如实表述为近似值，一律不得暗示为真题考频。** 这是不可协商的红线：宁可文案啰嗦，也不能让用户误以为我们在统计真题。

**禁止使用的表述**（无论中文或英文 UI、文案、引导、空状态，一律禁用）：

| 禁用表述 | 问题 |
| :-- | :-- |
| 「雅思考频」「真题出现 27 次」「历年真题命中次数」 | 直接虚构数据来源 |
| 「考过的义项」「必考义项」「考点命中率」 | 暗示我们有真题语料 |
| 「官方词频」「剑桥官方标注」 | 冒用官方背书 |
| 仅标注数字而不标注口径（如卡片上只显示「27」） | 无口径即默认被理解为真题计数 |

**五处必须落到位的 UI 措辞建议**（可直接交给设计师 / 前端，允许在此基础上微调标点）：

| # | 位置 | 措辞建议 | 说明 |
| :-- | :-- | :-- | :-- |

## 16. 术语表

| 术语 | 含义 |
| :-- | :-- |
| 义项 | 单词的一个具体词性 + 含义，如 address 的「v. 处理，解决」 |
| `senseWeight` | v0.3 引入的义项合成权重（0–100），由公开词表三层加权得出，替代原「考频」 |
| `kind: ESTIMATED` | 标记该权重为估计值而非真实考题计数 |
| Tier | 核心 / 进阶 / 拓展，由 senseWeight 判定，决定学习优先级与北极星指标分子 |
| 熟词僻义 | 非常见首义、但在学术英语中高频的义项 |
| 主义项卡 / 僻义卡 | 以义项为单位的学习卡片 |
| 学习日 | 按日切划分的一天，默认 04:00 至次日 04:00 |
| 每日首评 | 某卡在一个学习日内第一次提交的评分，唯一进入 FSRS 的评分 |
| 过轮窗口 | 考前最后 \(B\) 天，用于全量复习核心卡片 |
| 核心覆盖率 | 考试日预测 \(R \ge 0.9\) 的核心卡数量 ÷ 核心卡总数 |
| ADAPTED | 仿真例句标记，MVP 数据包唯一的例句出处类型 |
| $R$ | FSRS 预测的回忆概率 |
