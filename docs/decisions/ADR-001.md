# ADR-001: 前端框架与构建工具链

## Status

Accepted（2026-10-21）。含 1 项对 PRD §8.1 的偏离（React 18 → React 19.3.1）与 1 项浏览器下限上调（iOS Safari 16 → 16.4），均已在 `docs/02-ARCHITECTURE.md` §0.2 登记，待 team-lead 确认后转为无偏离。

## Background

ExamFlow Vocab 是面向雅思考生的自适应背单词 Web（PWA），MVP 无后端、无 AI，全部数据与计算在浏览器本地。PRD §2.3 要求"首次加载完成后断网，学习、复习、备份 100% 可用"；PRD §1.2 首发平台为桌面 Chrome / Edge / Safari 最新两个大版本 + iOS Safari 16+ / Android Chrome。

由此产生的约束：

1. 产物必须是**纯静态资源**，可托管在任意静态 CDN，无 Node 运行时。
2. 构建必须产出**版本化 hash 文件**，以便 Service Worker 预缓存与增量更新。
3. 样式方案必须支持**语义化设计令牌**，以便落地 P0「禁止硬编码颜色」并支持静态检查。
4. 领域层（调度算法）必须是**纯 TypeScript、不依赖 DOM**，可在 Node 中单测（PRD §8.2）。
5. MVP 阶段不引入团队不熟悉的技术。

候选方案与评分见 `docs/02-ARCHITECTURE.md` §1.1 / §1.2；对比过的方案包括 Next.js（App Router）、Vue 3 + Vite、Taro 3 / uni-app、Tailwind 3.4.19 + PostCSS、CSS Modules、UnoCSS。

## Decision

采用 **Vite 8.3.4 + React 19.3.1 + TypeScript 7.0.2 + Tailwind CSS 4.3.3（`@tailwindcss/vite`）** 的 SPA 组合。版本号均为本机 `npm view` 实测值，见架构文档 §2。

配套决定：

1. **React 19.3.1 而非 PRD 所写 React 18**：registry 实测 latest 为 19.3.1，React 18.x（末版 18.3.1）已进入维护态；`lucide-react@1.60.0` peer 为 `^16.5.1 || ^17 || ^18 || ^19`，`dexie-react-hooks@4.4.0` peer 为 `react >=16`，均支持 19；本项目不依赖任何 18-only API。回滚成本仅为 `package.json` 4 行。
2. **`@vitejs/plugin-react@6.1.2`**：其 peer 为 `vite ^8.0.0`，与 Vite 8.3.4 匹配；oxc / babel 相关 peer 已核验为 optional，无需安装。
3. **Tailwind v4 走 `@tailwindcss/vite` 插件，不配 PostCSS**：v4 的 `tailwindcss` 包本身不是 PostCSS 插件；同时启用 `@tailwindcss/postcss` 与 Vite 插件会冲突。不再创建 `tailwind.config.js`，配置改在 `src/styles/theme.css` 的 `@theme` 块。
4. **TypeScript 锁 minor（`~7.0.2`）**：TS 7 是原生端口大版本，minor 间可能有行为差异。
5. **状态管理不引第三方库**：学习会话用 `Context + useReducer`，持久数据用 `dexie-react-hooks` 的 `useLiveQuery`。唯一真相源是 IndexedDB，避免内存 store 与持久化数据双源不一致。
6. **弹窗一律用原生 `<dialog>` + `showModal()`**：自带焦点循环与 Esc 行为，不引 Radix / MUI / shadcn 等组件库。
7. **图标库锁定 `lucide-react@1.60.0`**，唯一出口 `src/ui/icons.ts`，尺寸只允许 16 / 20 / 24 px，ESLint `no-restricted-imports` 禁止其它文件直接 import。
8. **不引 `date-fns` / `dayjs`**：时间需求仅为"日切学习日键"与"距考天数"，自研 `src/domain/day.ts`（约 60 行），可精确控制日切语义并避开 DST 坑。

## Consequences

正面：

- 纯静态产物 + 版本化 hash，与 Workbox 预缓存天然契合，离线目标（PRD §2.3）是默认能力而非额外工作。
- Tailwind v4 的 `@theme` 让"语义令牌"落在 CSS 变量上，P0「禁止硬编码颜色」可被正则门禁机械校验。
- 依赖数量控制在 7 个运行时依赖，MVP 期的供应链风险与升级成本都小。
- 领域层零 DOM 依赖，可在 Vitest 中用固定时钟单测日切、考期截断、队列与撤销。

负面 / 代价：

- **浏览器下限上调**：Tailwind v4 依赖 `@property` 与 `color-mix()`，官方明示不支持 Safari < 16.4 / Chrome < 111 / Firefox < 128。PRD §1.2 写的 "iOS Safari 16+" 与之冲突。若产品坚持 16.0，须改用 `tailwindcss@3.4.19` + PostCSS 插件并重写令牌定义方式。
- **React 19 与 PRD 文字不一致**：需要 team-lead 显式确认，否则后续评审会反复质疑。
- **Tailwind v4 无 `tailwind.config.js`**：团队若习惯 v3 的 JS 配置与 `content` 扫描，需要适应 CSS-first 工作流。
- **TS 7 原生端口**：部分 ESLint / 类型插件对 TS 7 的支持可能在 minor 间波动，故锁 minor 并把 `typecheck` 作为硬门禁。
