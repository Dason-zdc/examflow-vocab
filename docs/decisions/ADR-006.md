# ADR-006: US-08 改为义项级同义替换，交付 v1.6.0

## Status

Accepted（2026-10-22）。**取代 ADR-005 的第 1~3 条裁定**（M1 不做 / P1 用 seq 对齐选最佳 synset / 质量门槛二选一）；
ADR-005 第 4~6 条（verify 增补约束、词根不冒充同义、UI 契约）继续有效，其中第 5 条的 UI 契约按本 ADR 升级。

## Background

ADR-005 的结论是「现有免费数据源达不到词汇产品级可靠标准」，证据是 WordNet 义项对齐后覆盖仅 61.6%、
约 20~30% 义项错配。这个结论的数据没错，但**归因错了**：错配不是 WordNet 的，是消费方式的。

同期另一个项目 SynsetLens（`synset-lens/analysis/requirement-analysis.md`）把同一问题拆到根因：

| 编号 | 根因 | 在本项目里的具体形态 |
| :-- | :-- | :-- |
| RC1 | 主键用 `word` 而不是 `(word, sense)` | `Word.synonyms` 数组，跨义项求并集 |
| RC3 | 释义从词形取，不绑义项 | 贴 `senses[0].cn`（最高频释义）给每个候选 |
| RC5 | 丢弃搭配框架 | `consist of` 与 `consist in` 的候选混成一个列表 |

旧实现 `scripts/enrich_pack_synonyms.mjs` 逐条命中：按词性取前 2 个同义集求并集、候选只带
`{lemma,pos,cn}`、`cn` 取该词首义。实测产物：

```
consist   → lie「躺着」、dwell「居住」        ← 这两个词只对 consist in（在于）成立
comprise  → 缺失                              ← consist of 唯一正确的替换词，因为它排在第 4 个义项
trend     → tendency / cut / curve / sheer    ← sheer 属于另一个义项
demonstrate → show / present / establish / exhibit  ← 与本卡「证明、表明」不同义的是 exhibit
```

也就是说 ADR-005 观察到的 20~30% 错配，是词级并集 + 词级释义这两个决策的必然结果，
换数据源（Moby / Webster / BabelNet）解不了——它们同样是词级结构。

## Decision

1. **同义关系的主键改为 synset。** 数据落在 `sense.synonymGroups[]`，每组一个 `synset` + 英文释义
   + 可选搭配框架；`Word.synonyms` 字段整体下线，`packVerifier` 不再接受词级同义。
2. **同义严格等于同 synset。** 上下位、类义、词根词族不冒充同义（延续 ADR-005 第 6 条）。
   宁可变短：没有同义集成员就输出空。
3. **候选带五态可用性判断**：`DIRECT`（可替换）/ `INFERRED`（框架一致）/ `REWRITE`（需改写，
   必带模板）/ `CONFLICT`（搭配不符，必带理由）/ `UNKNOWN`（待验证）。UI 按徽章呈现。
4. **ETL 独立成 `scripts/etl_synonyms.py`**（延续 ADR-005 第 2 条「不并入 etl_build_pack.py」），
   直读 Open English WordNet 2021 的 SQLite，纯标准库、可离线、无 npm 依赖。
   `etl_build_pack.py` 同步停止产出词级 `synonyms`（并拒绝该字段重现），旧
   `scripts/enrich_pack_synonyms.mjs` 与 `scripts/build/synonym-seeds.json` 一并删除——
   一个字段只能有一个生产者。
5. **中文释义绑义项：用中文义项段求交，不做翻译。** 卡片中文是同词性多义合并的结果
   （平均 2.8 个义项点，88% 的卡如此），本身不是义项级释义；候选的中文取自候选词词条
   （库内用数据包 `cn`，库外用 ECDICT `translation`，与数据包同源），**与卡片中文义项段求交，
   唯一重合的那一段才是该义项的中文**：
   `consist`（由…组成；在于）× `comprise`（包含、由…组成）⇒ 唯一重合「由…组成」；
   `dwell`（居住、居住(于)）与卡片无重合 ⇒ 不贴。重合即义项对齐证据，禁止机器翻译。
6. **数据源与许可**：OEWN 2021（CC BY 4.0）写入 `manifest.sources`；词库内 `oewn:2021` 缓存于
   `scripts/.cache/wn.db`（约 109 MB，不入库，同 Tatoeba 语料口径）。
7. **卡片粒度适配**：本项目一张卡是「一个词性的一个义项」，而 ECDICT 的 `cn` 把同词性多义合并了。
   因此一张卡可能对应多个 synset——每组必须带英文释义才不会歧义，且每组最多 3 个、每候选集最多 4 个。

## 判定逻辑（与 SynsetLens 的差异）

SynsetLens 的查询是「(词, 搭配) → 替换词」，本项目没有查询串，只有卡片。因此判定改成
「查询词的该义项实现 vs 候选词在该 synset 的实现」，并用两条红线压住误报：

- **介词改写模板只在义项 gloss 本身声明了框架时生成**（`be composed of` → of，`originate (in)` → in）。
  否则 `hold in place` 里的 in 会被当成搭配，产出 `maintain O → hold in O` 这种错句子。
- **官方子类框架判定一致（SAME）时，介词差异按状语处理**，不判冲突。
- 紧跟 be 动词的过去分词（`is comprised in this paper`）不计入主动句框架。

## Evidence（2026-10-22 实测）

数据包 v1.6.0：1999 词 / 2957 义项 / 4017 义项分组 / 7693 个候选。

| 指标 | 旧（v1.5.0，词级并集） | 新（v1.6.0，义项级） |
| :-- | --: | --: |
| 有同义数据的词 | 1597 / 1999（79.9%） | 1574 / 1999（78.7%） |
| 有同义数据的义项 | 不适用（词级） | 2034 / 2957（68.8%） |
| 候选能说明属于哪个义项 | 0% | 100%（4017 组全部带 gloss） |
| 候选带可用性判断 | 0% | 100%（五态） |
| 候选中文正确绑定义项 | 0%（贴词级最高频释义） | 21.5%（1657/7693，义项段求交） |
| `consist of` 的正确答案 comprise | 缺失 | REWRITE + `consist of O → comprise O` |
| `consist in` 与 `consist of` 的候选隔离 | 否 | 是（分组隔离，`frame=in` / `frame=of`） |

五态分布：DIRECT 7229（94.0%）、INFERRED 354（4.6%）、REWRITE 95（1.2%）、CONFLICT 13（0.2%）、UNKNOWN 2（0.03%）。

**代价是覆盖降了 1.2 个百分点**（23 个词从「有候选」变成「没有」）——那些词的同义集成员被过滤掉了
（词组、屈折变体、古体拼写、粗口、超出 3~14 字母）。这是刻意的：宁可少一个候选，不可多一个错候选。

## Consequences

正面：

- 同义替换可以按义项展示，用户在 `consist` 卡上同时看到「在于 → dwell/lie」与「由…组成 → comprise」，
  这是旧实现给不出的信息，也覆盖不了的信息。
- 五态把「能不能直接用」变成数据里的字段而不是用户的判断，`REWRITE` 直接给模板。
- 数据可审计：每个候选能回溯到 synset、gloss、搭配框架；`--verify-only` 与 `npm test` 双向把关。
- 去掉对 `wordnet-db`（npm）的运行时依赖，ETL 变成纯 Python 标准库。

负面 / 代价：

- **PRD US-08 的标杆示例仍不产出**：`increase` 不在 2000 词包内，且 WordNet 把 `surge / escalate /
  proliferate` 放在各自独立的 synset，严格同义永远拿不到。本 ADR 明确不承诺该示例，
  若要「同类学术近义词」需另开 ADR 做同类词分区（hypernym 兄弟），不得复用 `synonymGroups` 语义。
- 义项级中文只覆盖 21.5% 的候选：求交要求「候选词条里确实有这个中文段」，跨表述
  （`dwell` 与「在于」无共同字面）就贴不上。UI 仍以英文 gloss 为主，补齐需要人工编写义项级
  中文释义表（SynsetLens 的 CD1 同款取舍），并保证不引入词级贴附。
- 介词槽仍来自 gloss + 语料的启发式，被动句与状语是已知误差源；金标评测集仍缺（SynsetLens §4 同款欠账）。
- 数据包体积 +0.2 MB（5.9 → 6.1 MB），首屏加载的 E2E 冒烟用例需要放宽到 20s（并行跑测试文件时）。
