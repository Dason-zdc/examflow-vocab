# ADR-009: 学习卡内容红线从「不写解释」改为「事实可核、解释标注」

## Status

Accepted（2026-10-23）

## Context

前几轮迭代把「不臆造词源」执行成了「卡片上不出现任何解释性文字」：

- 词根块只给拆解与机械直译，`consist → 共同站立`，离「由…组成」很远，用户读完不知道怎么用；
- 形近词用编辑距离自动生成，`consist` 推的是 `consult / contest / convict`，没有一条说清区别；
- 同义替换摊五态徽章（可替换 / 框架一致 / 需改写 / 搭配不符 / 待验证），信息量大于学习所需；
- 四步法（拆解 / 溯源 / 重组 / 织网）占满一屏，实际阅读路径只有一句「这词怎么记」。

结果是「不写错」做到了，「能记住」没做到。而用户真实需要的三类内容性质不同：

| 内容 | 举例 | 能否由模型生成 | 出错代价 |
| :-- | :-- | :-- | :-- |
| 事实 | `sist` 源自拉丁语 *sistere*（站）；`consist of` = `comprise` | 不能（必须查表） | 高：记错词源、用错搭配 |
| 桥接 | `con(一起) + sist(站) → 站到一起` | 可起草，须审 | 中：推演读不通 |
| 口诀 | `affect 是 v.（Action）/ effect 是 n.（End result）` | 可起草，须审 | 低：不好记而已 |

把三者按同一把尺子管，只会让前两类拖累第三类。

## Decision

红线改为**分层**：事实继续严格，解释允许人写或 AI 起草，但必须标注。

### 1. 三层内容与契约

| 层 | 允许来源 | 落库字段 | UI 标注 |
| :-- | :-- | :-- | :-- |
| FACT 事实 | 人工词表 / WordNet / Wiktionary，**AI 不得生成** | `affix-lexicon.json` 的 form/cn/origin/sourceWord；`synonymGroups.synset`；`confidence` | 「人工校订」 |
| BRIDGE 桥接 | 人工撰写；或 AI 起草 + 人审 | `curated[word].literal` + `atoms` + `authoredBy` | 「人工助记」/「助记 · AI 起草」/「助记 · 已复核」 |
| MNEMONIC 口诀 | 人工撰写；或 AI 起草 + 人审 | `content/confusables.ts`、`content/ieltsRewrites.ts` | 区块标题即标注，不再逐条加徽章 |

`authoredBy` 为三态，**不允许缺省冒充 HUMAN**：`HUMAN` / `AI_DRAFTED` / `AI_REVIEWED`。历史条目缺省视为 `HUMAN`（那些确实是人工写的），新条目必须显式写。

### 2. 词根：四步压成一行记忆链

```
con(一起) + sist(站) → 站到一起 → 由…组成        同根：insist · resist · assist
```

- **只上人工背书的链**：`Morphology.showOnCard = confidence === 'CURATED'`。自动拆分只进词根库（`RootsView`），不上学习卡。这条是硬约束：`corporate → 使身体`、`emerge → 使…工作` 这类半成品宁可不显示。
- **同根词只挑 2–3 个已学过的**：以 `cards.fsrs.reps > 0` 为「学过」，按家族顺序取前 3 个；一个都没学过就不显示这一行。
- **直译不叠「的」**：拼接一律用短义（`AffixEntry.literal`），不用教学义（`cn` 含「…」「的」）。`…的行为、结果` 曾拼出「使标记的的」。
- **组合后缀当一个整体**：`-ification` / `-ication` / `-ization` / `-ically` / `-ibility` 等入表，不让 DP 拆成 `-ific + -ation` 两截模板。`identification` 现在切 `ident + ification`。
- **链尾词义默认遮住**：点「?」才出现，把阅读材料变成一次主动回忆。查词弹窗（compact）不遮，那里目标是查义。

### 3. 易混词与改写拆成两个独立区块

| 区块 | 触发条件 | 数据源 | 展示上限 |
| :-- | :-- | :-- | :-- |
| 易混词 | 命中人工高危清单优先；未命中降级为「词形相近」 | `content/confusables.ts`（24 对，自撰）→ 回退数据包 `confusables` | 人工 1 对（`lapses>0` 时 2 对）；回退 2 个词，只给词+中文，不展示 ETL 模板句 |
| 雅思改写 | 该义项有改写数据 | `content/ieltsRewrites.ts`（29 词，自撰）→ 回退 `synonymGroups` 的 `REWRITE` 候选 | 每组 2–3 条 |

- 五态徽章**只保留「需改写」一种**。`可替换 / 框架一致 / 搭配不符 / 待验证` 不再出现在学习卡上。
- **收敛的是徽章，不是候选**：没有人工改写种子时，WordNet 义项级同义照常展示（最多 2 组 × 2 条），只是不打徽章。否则「同义替换」等于被砍掉——这正是 2026-10-23 那次修正的原因。
- 改写每条必须带中文。允许短语（`a multitude of`、`give rise to`）。
- 义项对不上就不贴：`decline` 的「下降」改写不挂到「婉拒」义项（`sense` 片段匹配）。

### 4. 错误驱动的当前口径

`confusables` 的 ETL 结果（编辑距离 + 音近 + 共享前缀）**降级为回退**：有人工高危对时完全不出现；没有时以「词形相近」展示最多 2 个词，只给词与中文释义，不展示「拼写在第 N 个字母处不同」这类模板句。

「按错选词优先展示」暂用 `card.fsrs.lapses > 0` 近似：答错过的词允许多看一对。真正的「你在这道二选一里选了哪个」需要题型支撑，本轮不做——新增 `confusablePicks` 表要改 Dexie schema、同步协议与备份格式，收益不抵成本。等选择题题型立项时一并做。

## Consequences

**变容易**

- 卡片背面从「四步表格 + 五态徽章 + 8 个同根词」收敛为「一行链 + 1 对易混 + 3 条改写」，阅读路径短了一半。
- AI 起草的记忆链可以批量补，不再被「必须人工逐词写」卡住产能。

**变难**

- 记忆链覆盖率先降后升：`showOnCard` 收紧后 IELTS 包只有 59/1999（3.0%）上卡。
  接入 Wiktionary 对照 + 三批起草后为 **333/1999（16.7%）**，curated 351 条；能切分的 467 个词里，其余 134 个仍是自动拆分，只进词根库。
- 多了 `authoredBy` 这一层元数据，ETL 与人工补数据都要带。
- 易混清单是人工维护的 24 对，覆盖不到全库；没命中的词这一块直接不出现（这是有意为之，不用自动结果凑数）。

**明确不做**

- 不用编辑距离结果冒充「高危易混」——回退时标题与说明都必须写明「未必是高频混淆」。
- 不在学习卡上展示 `DIRECT / INFERRED / CONFLICT / UNKNOWN` 徽章。
- 不让 AUTO 拆分的词上学习卡（词根库仍可查）。

## 修正记录：2026-10-23「两块都消失了」

首版把口径执行成「没有人工数据就整块不渲染」，实测覆盖：

| 块 | 首版可见 | 原因 |
| :-- | :-- | :-- |
| 易混词 | 48 / 1999（2.4%） | 只认 24 对人工清单，ETL 的 1457 个词全被停用 |
| 同义替换 | 106 / 1999（5.3%） | 回退只取 77 个带 REWRITE 的词，7229 条 DIRECT 候选全被过滤 |

合计 **92.4% 的卡片两块都空**，用户直接反馈「怎么没了」。这不是降噪，是删功能。

修正后的口径：**人工数据优先，缺失时降级展示，而不是整块消失**。降级层只做减配（少条数、去徽章、去模板句），不改变信息性质。

## 已知限制：ECDICT 的 sense 粒度粗于 WordNet synset

**现象**：`conclude` 的卡片背面出现 `reason` / `resolve` 当同义替换。

```
sense s_conclude_v_bring   v.  结束、作结论、推断     ← 三个义项合并成一个 sense
enDef: bring to a close                              ← 只描述「结束」
  ├ decide by reasoning → reason        ← 其实属于「推断」
  ├ reach a conclusion after deliberation → resolve  ← 其实属于「决定」
  └ come to a close → close             ← 属于「结束」，但搭配不符
```

**根因**：ECDICT 的一个 sense 是「一个词性 + 多义合并」，而 WordNet 按细分义项给 synset。
ETL 忠实按 synset 挂候选，于是同一 sense 下并排了三个不同义项的同义词。
ADR-006 的「义项级同义」在数据层就没有真正对齐——这是粒度错配，不是同义判断错。

**当前修法（展示层）**：用 `sense.enDef` 与各 synset `gloss` 的实词重叠数挑组，
只展示得分最高的一组（并列时最多两组）；全部为 0 时退回第一组，不臆测。
同时补回 `CONFLICT` 的理由与中性标记「搭配不同」——去掉徽章不等于去掉否定信息。

**修法覆盖**：1258 个多组义项里，约 62% 能靠 enDef 选出正确组（`present`、`contribute`、
`procedure`、`theme` 都验证过）；38% 退化，原因是 enDef 为空（15%）或 enDef 本身与中文义项
错位（如 `demonstrate` 的 enDef 是「游行示威」，但中文义项是「证明、演示」）。

**彻底修法（未做）**：把合并 sense 按 synset 拆成多个 sense。会改变卡片数、FSRS 调度单元、
例句关联与词库统计，属结构性改动，需要单独一轮评估。在那之前，展示层选组是成本最低的止损。

## 数据核对结果（kaikki / Wiktionary）

| 项 | 结果 |
| :-- | :-- |
| 词源覆盖 | 1979 / 1999（99.0%） |
| 现有 curated 与 Wiktionary 完全一致 | 2 |
| 切分粒度不同（共享成分） | 4（telephone / psychology / construction / incredible） |
| 成分完全对不上 | 2（communication / prescription，均为「拉丁词根直切」vs「英语派生链」，不构成错误） |
| Wiktionary 给出前/后缀构词模板且成分在词表内 | 10 |

结论：**没有发现词源错误**（唯一真错的 `illegal` 已在上一轮 block 掉）。Wiktionary 的构词模板覆盖率低（英语词条多用 `{{inh}}`/`{{der}}` 讲来源），所以它的价值是**核对**现有切分，召回仍靠词表自身的 DP + 逐条起草。

## Follow-ups

1. **批量补记忆链（已完成首轮）**：`scripts/fetch_kaikki.py` 分段并发下载 kaikki 英语 dump（509 MB，单连接被限速到 90 KB/s，12 段 Range 并发约 1 MB/s）；
   `scripts/etl_wiktionary_etymology.py` 流式扫描 149.9 万行，命中 1979/1999 词（99%）；
   `scripts/apply_memory_chains.py` 分三批写入 274 条 `AI_DRAFTED` 记忆链。覆盖 3.0% → 16.7%。
   **剩余工作**：把 `AI_DRAFTED` 抽检升级为 `AI_REVIEWED`；覆盖率继续往上走只需扩 `OVERRIDES`（脚本幂等，重复跑会跳过已有条目）。
2. **易混清单扩到 60 对**：优先覆盖雅思写作高频混淆（`comprise/compose`、`affect/effect` 已收；补 `imply/infer`、`lie/lay` 之外的 `principal/principle` 已收）。
3. **改写数据接入构建期**：目前 29 词是手写种子；后续按义项从 WordNet 同义集 + 搭配语料生成候选，人工筛「写作常用」。
4. **错选日志**：与选择题题型一起做，届时把 `lapses` 近似换成真实干扰项记录。
