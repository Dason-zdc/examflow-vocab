# ADR-005: US-08 同义词数据 M1 不做，列 P1

## Status

Accepted（2026-10-21）。依据 devops 侧四方向只读调研（WordNet 同义集 / ECDICT 字段 / 开源同义词表 / 词根派生降级）实测证据裁定。

## Background

PRD US-08 要求「同义替换可达性」。数据契约侧 `Word.synonyms: Synonym[]` 早已就绪（`src/domain/types.ts`，架构 §6.3 第 632 行），但 ETL 从未产出该字段：2000 词数据包 `synonyms` 0/2000 填充，README §7 登记为缺口 G-3，OPEN-DECISIONS 登记为 OD-23。缺口本身不是新信息，新信息是调研结论：**现有免费数据源达不到词汇产品级「可靠」标准**。

调研实测要点：

1. **WordNet 3.0（NLTK 发行版）**：zip 10.3 MB / 解压 35 MB / 117,659 synset；WordNet License 允许商用、免版税、须保留版权声明，与 ECDICT 现有授权链兼容。本词表原始覆盖 1994/2000（99.7%），但按义项对齐（Sense.enDef 与 synset definition 做 token 重叠选最佳）后仅 **1232/2000（61.6%）**获得同义词，且存在约 20~30% 义项错配噪声（contribute→give、trend→tendency、demonstrate→march 一类），粗口等合规红线项必须黑名单兜底。
2. **US-08 标杆场景无法产出**：PRD 示例 increase 对 surge/escalate/proliferate 中，`increase.v.01` 同义词为空，surge / escalate / proliferate 均不在其同义集——WordNet 把学术近义词拆成各自独立的 synset。标杆场景缺失是「不可靠」的决定性证据。
3. **ECDICT 无同义词数据**：「sw 字段是同义词」为误传——实测 CSV 列为 `word, phonetic, definition, translation, pos, collins, oxford, tag, bnc, frq, exchange, detail, audio`，无任何同义列；本地 README-ECDICT.md 第 147 行明确 `sw` 是 strip-word（模糊匹配键值）缩写。ETL 既有注释「ECDICT 无可靠同义词源」属实。
4. **其他开源表**：Moby Thesaurus II（公有领域，95.2% 覆盖）无词性无义项，中位 141 个同义词/词，过滤后仍有 76~98 个，量级不可用；Webster 1913 义项级人工质量高但仅 31% 覆盖且词汇过时（priority→antecedence 一类）；BabelNet 为 CC BY-NC-SA，许可不符；FinNLP/synonyms 为 WordNet 派生无增益。
5. **词根派生不能替代**：wordroot.txt 覆盖 993/2000 词（如 ced/cess 根下 access/concede/exceed），但共享词根 ≠ 可互换——把它标成「同义替换」会教用户错误替换关系，违背项目「不臆造」的数据文化。若产品要「词族记忆」价值，只能作 CardBack 独立可选模块。

## Decision

1. **M1 不补 `synonyms` 数据，不实现同义词 UI 区块**。US-08 维持「未交付（数据阻塞）」状态，README §1 与 §7 G-3 保留登记。
2. **P1 数据源首选 WordNet**（独立脚本 `scripts/etl_synonyms.py`，不并入 `etl_build_pack.py`——后者 1401 行已是行数门禁豁免的历史文件，新逻辑不得并线）。管线：逐 sense 取含该词 lemma 的 synset → enDef 与 synset definition token 重叠选最佳 → `lemma_names()` 过滤（单单词 / ≤15 字符 / 黑名单 / 排除本词）→ 补 `pos` 与 `cn`（ECDICT translation 首义，与 confusables 同源）→ 每词 ≤6 条。
3. **P1 质量门槛二选一**（排期时定）：全量输出 + 人工抽检 100 词修复（约 3 人日）；或高精度门槛（definition 重叠 ≥2 token 且 synset ≤5，牺牲覆盖换精度，预计 40~50% 覆盖 / >90% 精度，约 2.5 人日）。备选升级：Tier A 300 词人工撰写同义替换表（质量最高、直接命中高频场景，2~3 人日）。
4. **`verify()` 增补 synonyms 约束**（lemma ≠ 本词 / pos 合法 / cn 非空 / 数量上限）；manifest `sources` / `license` 增加 WordNet 条目与 Princeton 版权声明；DATA-QUALITY.md 增加覆盖率行。
5. **UI 契约先行**：同义区按「`synonyms` 非空才渲染」实现（P1 数据到位即上线，约 30 行，无需返工）；M1 不写这 30 行——0/2000 数据下渲染永不可见，只会成为无测试覆盖的死代码。
6. **词根相关词不进入 US-08**。如后续产品要做词族模块，另开 US/ADR，不得复用 synonyms 字段语义。

## Consequences

正面：

- 不在 M1 展示约 20~30% 错配的替换关系——词汇产品里错误的「同义替换」比没有更伤信任，且直接违反项目「不臆造」的数据文化与 T-19 合规姿态。
- 避免为赶 M1 引入粗口过滤这类合规兜底逻辑（get.v.01 串出 fuck_off/bugger_off 已实测），自动管线的风险面在 M1 完全不暴露。
- ETL 主文件不超行数门禁，数据契约（`Word.synonyms` 类型、manifest 字段）保持稳定，P1 只增数据不改结构。

负面 / 代价：

- US-08 在 P1 前完全不可用，「同义替换」对 M1 用户不存在。
- P1 需投入约 3 人日数据管线 + 抽检修复，且即便上线也只有 40~61.6% 词有同义词（取决于质量门槛路径）。
- 若竞品在 M1 窗口期上线同义功能，本项目该维度落后一个版本周期。
