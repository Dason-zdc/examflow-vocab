# ADR-003: 本地存储与备份

## Status

Accepted（2026-10-21）。

## Background

MVP 无后端，全部用户数据留在浏览器。PRD §6 / §7.2 与 §9 的硬要求：

1. IndexedDB + Dexie，按实体分表；启动时申请持久化存储。
2. **一次评分提交 = 更新 Card + 写入 ReviewLog，事务原子执行**。
3. `schemaVersion` 变化时执行迁移，**迁移前自动生成一份本地备份**。
4. 导出全部进度为**单个 JSON 文件**；导入后卡片状态、复习日志、生词本、笔记与导出前一致；超过 7 天未备份时提示。
5. 数据丢失是最高风险项之一（PRD §9）：iOS Safari 等会在长期未访问时清理本地数据。
6. 领域层必须纯 TS、不依赖 DOM（PRD §8.2），因此存储实现不能反向污染领域层。

对比过的方案：`idb`（薄封装原生 IndexedDB）、裸 IndexedDB API、localStorage。localStorage 无事务且 5MB 上限装不下数据包与复习日志；裸 API 与 `idb` 都要手写事务与索引，成本高于收益。

## Decision

1. **Dexie 4.4.6 + `dexie-react-hooks` 4.4.0**（实测 peer：`dexie >=4.2.0-alpha.1 <5`、`react >=16`）。数据库名 `examflow-vocab`，Dexie version 1，与 `Settings.schemaVersion` 保持一致并双向校验。
2. **表结构**（主键 / 索引）：
   - `cards`：`id`（`${exam}:${senseId}`）；索引 `exam`、`wordId`、`senseId`、`dueAt`、`suspended`、`[exam+dueAt]`
   - `reviewLogs`：`id`；索引 `cardId`、`studyDay`、`reviewedAt`、`[cardId+studyDay]`
   - `settings`：`id`（固定 `'default'`）
   - `userWordMeta`：`wordId`
   - `customWords`：`id`（`cw_` 前缀）—— MVP 建表不用（S-02 为 P1）
   - `packChunks`：`[exam+version+n]`；索引 `exam`、`version`
   - `sessionState`：`id`（固定 `'default'`）—— 队列快照 / current / stage / rating / undoEntry
   - `sweepPlan`：`studyDayKey` —— 考前过轮分配
3. **时间字段一律 epoch ms 整数**（字段名以 `At` 结尾，如 `dueAt` / `reviewedAt`），**禁止把 `Date` 对象写入 IndexedDB 或备份 JSON**。`lastFirstReviewDay` 是唯一例外，存 `'YYYY-MM-DD'` 学习日键字符串。理由：JSON 往返会把 `Date` 变成 ISO 字符串，导入后与原生 `Date` 混用会产生"能读、能写、但比较全错"的沉默逻辑错误。`storage/mappers.ts` 是唯一的双向转换点。
4. **事务边界唯一化**：`db.transaction` **只允许出现在 `src/app/transactions.ts`**，由 grep 脚本门禁。一次评分提交在单个 `rw` 事务内完成 `cards.put` + `reviewLogs.add` + `sessionState.put`。撤销同样是单事务（恢复卡片快照 + 按 `logId` 删日志 + 恢复队列快照）。
5. **事务体内只允许 Dexie 操作与纯计算**：FSRS 计算、队列推进、撤销快照全部在**进入事务之前**由 `domain/reviewCommitter.ts::buildCommitPlan`（纯函数）算完。事务内 `await` 非 Dexie Promise 会触发隐式提交并抛 `TransactionInactiveError`。
6. **依赖倒置**：`src/domain/ports/*.ts` 定义仓储接口，`src/storage/repositories/*.ts` 实现。领域层只 import 端口类型，不 import Dexie。
7. **持久化申请**：`navigator.storage.persist()` 放在"添加到主屏幕"引导后的**用户手势回调**中，不在启动流程静默调用；结果写入 `Settings` 并如实告知用户。iOS 16 之前该 API 恒返回 `false`，且仅 Home Screen 安装的 PWA 有资格。
8. **备份格式**沿用 PRD §7.2 并补 4 个字段：`appVersion`、`exam`、`packVersion`（导入时校验数据包版本匹配）、`schemaVersion`。导入规则：`format !== 'examflow-backup'` 拒绝；`formatVersion` 高于支持版本拒绝并提示升级；**导入前先自动导出当前数据**；默认覆盖，可选按 `updatedAt` / `reviewedAt` 合并；导入在同一 `rw` 事务内完成，失败整体回滚。
9. **迁移**：`schemaVersion` 变化时执行迁移脚本，迁移前自动导出一份本地备份；迁移与导入共用同一套事务与校验路径。
10. **备份提醒**：`Settings.lastBackupAt` 超过 7 天在首页提示（PRD US-07）。

## Consequences

正面：

- 单一真相源是 IndexedDB，`useLiveQuery` 直接投影，不引入内存 store，消除双源不一致（与 ADR-001 第 5 条一致）。
- 事务边界收敛到一个文件，可机械校验；撤销与提交走同一路径，撤销的正确性由同一批测试覆盖。
- epoch ms 统一让"备份往返逐字段一致"（T-12）成为可自动断言的测试，而不是靠人眼看。

负面 / 代价：

- `mappers.ts` 增加一层转换代码；所有读写必须经过它，绕过即产生类型与语义不一致（靠 ESLint + Code Review 约束）。
- `sessionState` 单表单行存储会在高频评分时产生较多整对象写入；2000 词规模下可接受，若出现卡顿再拆分为增量字段。
- fake-indexeddb 不支持 `navigator.storage.persist()` / `estimate()`，`persistence.ts` 必须允许注入 storage 对象才能单测；且集成测试禁止复用模块级 Dexie 单例（事务会 hang），每个用例新建随机名数据库并在 `afterEach` 删除。
