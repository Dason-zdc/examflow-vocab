# ADR-008 · 词根词缀四步法：人工词表 + 词素切分 + 构建期织网

> 日期：2026-10-23｜状态：已采纳（部分修订）｜补充 ADR-006 / ADR-007
> 修订：卡片展示形态由 **ADR-009** 从「四步」压成一行记忆链；切分算法与人工词表不变。
> 相关：P1-5 同源词群、US-06 点词即查、`src/content/morphology.ts`、`scripts/build_root_families.py`

## 1. 背景

词根功能此前由三块互不相干的数据拼成：

1. 数据包 `word.etymology`：只给**一个**词根与英文释义（如 `dic, dict（speak, declare）`），
   `build_etymology()` 仅在 ECDICT wordroot 的示例词表命中时生成，**不做前缀/后缀拆解**。
2. `word.wordFamily`：Wiktionary 词干召回。实测出现 `predict → root "pra"`、`members: []` 这类
   空壳或错根；`CardBackFamilies` 在 `members.length === 0` 时整块不渲染。
3. `splitMorphology()`：运行时按前后缀表贪心兜底，`information` 能拆，但无词源、无中文释义，
   且 `findRoot()` 用 `includes` 判词根，`city → cit` 这类误伤无法拦截。

用户要求按「拆解 → 溯源 → 重组推演 → 织网」四步记忆法重做：每个成分要有中文含义与词源，
第 3 步要能看出「字面义 → 实际义」，第 4 步要能从一个词根串出一串同根词。

## 2. 决策

### 2.1 词表是唯一真相源，人工校订

新增 `src/content/affix-lexicon.json`：113 个前缀 / 273 个词根 / 71 个后缀，每条含
中文教学义、直译短义、来源语言、词源原词、变体（`dic → dict`）。

- 中文释义**不由模型生成**，逐条按常用拉丁/希腊词根义书写；直译模板（`能{core}的`）单独存，
  避免把「教学义」与「机械直译」混为一谈。
- 同一份 JSON 被 TypeScript（运行时）与 Python（构建期织网）共同读取，字段口径只维护一处。
- 变体（`dic/script/cept`）归一到主条目，织网时不会把 `predict` 与 `dictionary` 分到两个家族。

此前 `scripts/roots.json` 的 809 个键里有 307 个逗号复合键（`dic, dict`、`-al2, -ial, -ual`），
运行时永远匹配不到；新词表在解析时展开变体并剥掉词性与序号标记。

### 2.2 切分用带阶段约束的 DP，而不是「见到词根就拆」

`analyzeMorphology()` 在词素边界上做动态规划，状态 = `(位置, 阶段)`：

```
阶段 0 前缀区 → 阶段 1 词根区 → 阶段 2 后缀区
```

约束与打分：

| 约束 | 取值 | 理由 |
| :-- | :-- | :-- |
| 字母全覆盖 | 每个字母必须属于某个成分 | 允许词尾不发音的 `e`；否则 `city` 会被拆成 `cit + y` |
| 词根必需 | 无词根 → 不输出 | 只有前后缀的「拆解」没有记忆价值，且极易误伤 |
| 前缀上限 | 2 个 | `un + pre + dict` 够用；再多基本是误判 |
| 后缀上限 | 3 个；2 字母后缀限词长与词根长 | `al/ic/fy/or/y` 单独设阈值，`y` 要求词根 ≥4 且词长 ≥7 |
| 组合词根 | 仅 `bene / male` | `benediction / malediction` 是真实复合，`verdict` 走人工校订 |
| 打分 | 词根 4.0/字母，前缀 2.2，后缀 2.4 | 偏向更长词根与更少成分；同分取成分更少、词根更长 |

同时维护一份 `blocked` 黑名单（`present`、`recover`、`portion`、`common`、`decade` 等 13 词）：
这些词能被上述规则拆出「形式正确、词源错误」的方案（如 `present = pre + sent(感觉)`），
属于已知误判，直接拒绝，不靠 UI 文案兜底。

### 2.3 口径分两档，宁可少展示

- `CURATED`：人工校订整词（29 个，含用户示例 `unpredictable = un + pre + dict + able`）。
- `AUTO`：按词表自动切分，UI 标注「自动拆分」，脚注写明「未逐词人工复核」。

不引入「大概像」的模糊拆分。2000 词包里能完整切分的是 **467 词（23.4%）**；其余不渲染区块。
这是有意为之：词根法最大的风险是给出错误词源，学习成本比「没有」更高。

### 2.4 织网在构建期生成，运行时只读

`scripts/build_root_families.py` 用同一份词表扫 45k 学习者词典，产出
`public/dict/root-families.json`（242 个词根 / 4037 条同根词 / 177 KB）：

- 每个词根取前 12 个高频词，按 ECDICT 词频排序；
- 同一派生链只留一个代表（`predict / prediction / predictable` 不占三个名额）；
- 公式由切分结果拼成（`pre(在前)+dict(说)+able(能…的)`），不用生成式文案；
- 运行时 `RootFamilyIndex` 懒加载 + 内存缓存 + Cache Storage，离线可用。

选构建期而不是浏览器端扫全量词典：45k × 273 词根的切分在 Node 里要几百毫秒到数秒，
会拖慢每次开卡；索引只有 177 KB，一次拉取即可。

### 2.5 词根库：让「织网」不依赖当前词

卡片背面的四步法只覆盖能完整切分的词（23.4%）。为了让「1 个词根 = 记一串词」这件事
对剩下的词也成立，新增导航页「词根」（`src/ui/RootsView.tsx`）：

- 直接读同一份 `root-families.json`，按家族大小排序，展示 242 个词根 / 4037 个同根词；
- 搜索同时命中词根、中文义与家族成员（如搜「说」或「predict」都能落到 dict）；
- 家族详情列全部成员与构词公式，词库外的词可一键加入生词本（复用 `addCustomWord`）；
- 数据与卡片共用 `RootFamilyIndex`，不额外增加请求。

这一步刻意不做「按字母 A–Z 翻词根」：词根不是单词，用户更常按语义找（「看」「说」「携带」），
所以默认按家族规模排序、搜索覆盖中文义。

入口有两个：

1. 桌面顶栏「词根」Tab；
2. 窄屏（<768px）顶栏「切换页面」菜单——此前只有 `md:flex` 的桌面导航，手机上根本进不去
   「词库 / 词典 / 词根」；菜单是本轮一并补的。卡片第 4 步也加了「打开词根库」跳转，
   由 `ExamFlowApp → StudyView → CardBack → MorphologyCard` 透传 `onOpenRoots`。

菜单必须渲染在 `<header>` **外面**：Header 的 `backdrop-blur` 会为 `position: fixed`
子元素创建包含块，放在里面会让遮罩只盖住 56px 的 Header（这是实现时踩到的坑）。

## 3. 后果

正面：

- 卡片背面从「一个英文词根」变成完整四步，第 4 步可直接点词查义、加入生词本。
- 词源口径可追溯：每个成分都能指到词表条目，公式不编造联想。
- 织网覆盖 242 个词根，用户即使遇到不能拆的词，也能从同根词反查（后续可在查词页扩展入口）。

代价与已知限制：

- **覆盖率只有 23.4%**。ECDICT 词根表长尾（`lys`、`pra`、`menthink`）大量不是真词根；
  补词表能提升，但边际收益递减，且每加一个词根都要人工核对释义。
- 机械直译在部分词上读不通（`inter-` 直译「之间」+ 词根），已在第 3 步明确标注
  「不等于词典释义」；`in-/im-` 的否定/向内二义按「有形容词后缀才否定」判断，仍有例外。
- 词尾 `e`、连接元音（`part+i+cip+ate`）尚未建模，`participate` 这类词仍不展示。
- `portion`、`portal` 等「形似词根但词源不同」的词靠黑名单拦截，新增词根时需回归抽样。

后续可选路线（未纳入本次）：

1. 部分拆解模式：只给「前缀 + 词根」或「词根 + 后缀」，用于约 500 个含已知词根但拼不满的词；
2. 连接元音与音变规则（`part+i+cip+ate`、`con+trib+ute`）；
3. 词根浏览页（按词根 A–Z 浏览 242 个家族），把织网从卡片内扩展到独立入口。
