# ADR-004: 离线与 PWA

## Status

Accepted（2026-10-21）。

## Background

PRD §2.3 要求"首次加载完成后断网，学习、复习、备份功能 100% 可用"；§2.3 还要求已缓存数据包下冷启动到首张卡可操作 P95 ≤ 2 s。MVP 的服务端依赖只有一个：静态 CDN 上的词库数据包（PRD §7.1）。

由此产生的约束：

1. 应用壳（HTML / JS / CSS / 图标）必须可离线导航，不能只靠 HTTP 缓存。
2. 数据包分块下载后必须**持久化**，且持久化的地方不能与 Service Worker 的 Cache Storage 争抢同一份数据。
3. 更新不能打断用户：学习中途被 reload 会丢掉未提交的评分。
4. 构建产物是版本化 hash 静态资源，预缓存清单应自动而非手写。

对比过的方案：手写 Service Worker、仅用 Cache API 不用 SW。前者需要自己维护 hash 清单，后者无法满足离线导航。

## Decision

1. **采用 `vite-plugin-pwa@2.0.0`（Workbox 7.4.1）**。实测 `vite-plugin-pwa@2.0.0` 的 peerDependencies 中 **`workbox-build@^7.4.1` 与 `workbox-window@^7.4.1` 是必装 peer**（`peerDependenciesMeta` 只把 `@vite-pwa/assets-generator` 标为 optional），因此 `workbox-build` 与 `workbox-window` 必须显式写进 `devDependencies`，否则安装告警且运行期可能取不到模块。
2. **`registerType: 'prompt'`，不用 `autoUpdate`**。SW 更新事件到达后显示提示条，**等本轮队列清空或用户点"下一轮"时再 reload**，避免中断学习丢状态。
3. **数据包不进 Workbox 预缓存**：
   - `globPatterns` 排除 `packs/**`；
   - 对 `/packs/**` 用 `runtimeCaching` 的 `NetworkFirst` + 独立 `cacheName`（仅作下载加速）；
   - **权威副本在 IndexedDB 的 `packChunks` 表**（见 ADR-003），SW 与 IndexedDB 职责不重叠。
   - SW 更新时只 `caches.delete()`，**绝不清理 IndexedDB**。
4. **首块随应用发布**：`public/packs/ielts/1.0.0/` 下放 `manifest.json` + `chunk-0.json` + `lemma-map.json`，保证首次安装后即刻可离线学习；其余块按需下载。
5. **manifest 图标**同时提供 `purpose: 'any'` 与 `'maskable'` 的 512 图标，避免 iOS 添加到主屏幕时裁切。
6. **`navigateFallback` 指向 `index.html`**，配合版本化 hash 产物，避免旧 SW 返回旧 HTML 引用已删除 chunk 导致白屏。
7. **校验路径依赖安全上下文**：`crypto.subtle` 仅在 HTTPS / localhost 下可用。局域网真机调试（`http://192.168.x.x:5173`）下不可用，`packVerifier` 在缺失时**明确报错并说明原因**，不静默跳过校验。真机调试走 HTTPS（自签证书 + 手机信任）或 Chrome 的 `#unsafely-treat-insecure-origin-as-secure`。
8. **E2E 离线断言**：Playwright 用 `context.setOffline(true)` 验证学习 / 复习 / 导出在断网下可用；另有一条错误流断言数据包分块被篡改后 `sha256` 校验失败、不写缓存并提示（PRD T-15）。

## Consequences

正面：

- 离线能力由构建插件自动生成预缓存清单，无需人工维护 hash。
- 数据包权威副本在 IndexedDB，与 ADR-003 的存储/备份路径复用同一套事务与迁移逻辑。
- `prompt` 更新模式把"更新时机"交给用户，消除了学习中断丢数据这一类最难复现的缺陷。

负面 / 代价：

- 必须显式安装 `workbox-build` / `workbox-window` 两个 peer，否则依赖树不完整。
- 用户可能长期停留在旧版本（点了"稍后"就忘了），需要产品侧决定提示条的留存策略与强制更新阈值。
- 双份数据（Cache Storage 的 `/packs/**` 副本 + IndexedDB 权威副本）会占用额外空间；在 `Settings` 中提供"清理下载缓存"入口，且清理只删 Cache Storage 与 `packChunks`，不动用户进度。
- iOS Safari 对长期未访问站点仍会清理 IndexedDB（ADR-003 第 7 条），PWA 本身无法兜底，必须靠备份提醒与引导添加到主屏幕。
