# ADR-002: 调度引擎 ts-fsrs 与考期适配

## Status

Accepted（2026-10-21）。含 1 项对 PRD §5.5 的事实性修正：ts-fsrs 5.4.2 默认算法为 **FSRS-6（21 个权重）**，不是 PRD / 原型中的 FSRS-4.5（17 个权重）。

## Background

产品成立的核心逻辑是"以考试日期决定什么时候复习"。PRD §5.5 要求：

1. 使用开源 `ts-fsrs`，**锁定具体版本**，不自研公式；默认参数用内置默认值。
2. 按**义项**建卡（主义项卡 + 熟词僻义卡，每词最多 3 张）。
3. 考期截断：`I_final = min(I_fsrs, max(1, D - 1))`，下次到期不晚于考前 1 天；距考 ≤ 1 天时为次日。
4. 目标留存率随考期提高：`D > 30 → 0.90`，`8 ≤ D ≤ 30 → 0.93`，`D ≤ 7 → 0.95`（PRD 标注为假设值，M1 校准）。
5. 每日首评：每张卡每个学习日**只有第一次提交的评分**进入 FSRS，同日重现 `sessionOnly = true`。
6. 北极星指标"考试日预测 R ≥ 0.9 的核心卡数"完全依赖 FSRS 的 stability 模型。

对比过的方案：自研 FSRS-4.5 公式（原型内联版）、Anki SM-2、自研 Leitner 盒。后三者要么违反 PRD「不自研公式」，要么缺少 stability 模型因而无法计算 R。

## Decision

1. **采用 `ts-fsrs`，精确锁版本 `5.4.2`**（`package.json` 写作 `"ts-fsrs": "5.4.2"`，无 `^`）。实测依据：`npm view ts-fsrs version → 5.4.2`；`6.0.0-beta.*` 已发布到 beta.15，漂移风险真实存在。
2. **考期截断不由 ts-fsrs 单独完成**。实测（本机，`enable_fuzz:false`、`enable_short_term:false`）：

   | 场景 | `maximum_interval` | 实际 `scheduled_days` |
   | :-- | :-- | :-- |
   | 新卡首次 Good | 1 / 2 / 5 / 36500 | **均为 3**（完全忽略该参数） |
   | 复习卡 S=60，elapsed=0 | 20 / 9 | 21 / 10（`maximum_interval + 1`） |
   | 复习卡 S=60，elapsed=10 | 20 / 9 | 21 / 10 |

   因此 `src/domain/scheduler.ts` 的 `scheduleReview()` 必须执行**自建夹取**：
   `intervalDays = clampInt(log.scheduled_days, 1, maxIntervalFor(D, mode))`，随后 `dueAt = studyDayStartTs(addDays(studyDayKey, intervalDays), dayStartHour)`。`maximum_interval` 仍传给 ts-fsrs，但只作辅助，**不得作为断言依据**。
3. **`enable_short_term: false` 固定写死**。实测开启后 `scheduled_days = 0`、`due = now + 10min`，与"每卡每学习日仅首评进 FSRS"直接冲突，到期列表同日反复命中。日内重复全部交给 `SessionQueue`（PRD §5.6）。
4. **`enable_fuzz`**：生产显式 `true`（避免到期卡堆积），单测显式 `false`（保证确定性）。实测 `generatorParameters()` 默认值为 `false`，故必须显式传，不能依赖默认。
5. **`request_retention` 按 `D` 动态注入**：`D ≤ 7 → 0.95`，`D ≤ 30 → 0.93`，其余 `0.90`；长期记忆模式（`D < 0` 或用户切换）恢复 `0.90`。
6. **每日首评判据**：`card.lastFirstReviewDay !== studyDayKey`。首评更新 FSRS 并写 `lastFirstReviewDay`；同日重现只推进 `SessionQueue`，日志 `sessionOnly = true`。
7. **撤销用整卡快照，不用 `fsrs.rollback()`**。实测 `rollback` 在本版可精确还原，但撤销范围还包含队列快照与日志删除，快照法跨版本更稳。
8. **评分映射**：不认识 / 记错了 → `Rating.Again`，模糊 → `Rating.Hard`，认识 → `Rating.Good`。MVP **不提供 Easy**（Q-07 决定前不加）。
9. **义项建卡规则由客户端派生，不写进数据包**：`src/domain/cardFactory.ts` 按 `examStats[exam].freq` 降序取主义项（并列时按 `senseId` 字典序升序破并列），再取前 2 个 `isEccentric` 义项作僻义卡，每词最多 3 张。`Card.id` 取值为 "exam:senseId" 形式，`senseId` 永不复用，跨版本进度可迁移。
10. **考期参数（阈值 7 / 30 天、留存率 0.90 / 0.93 / 0.95、过轮窗口 B）集中于 `scheduler.ts` 与 `planner.ts` 的常量区**，M1 用复习日志校准时不改结构只改值。

## Consequences

正面：

- 不自研公式，避免一套自研实现与 PRD 指标脱节的风险。
- 自建夹取让 `T-01`（`D = 10` → 到期 ≤ 9 天后）与 `T-02`（`D = 1` → 到期 = 1 天后）成为确定性断言，不随 ts-fsrs 内部实现漂移。
- 关闭 short-term 后状态机只有 `New` / `Review` 两态（实测：新卡评 Again 也直接进 `Review`），到期计算与"每日首评"语义一致。

负面 / 代价：

- **默认算法是 FSRS-6 而非 FSRS-4.5**（实测 `default_w.length === 21`，`FSRSVersion === "v5.4.2 using FSRS-6.0"`）。PRD §5.5 与原型演示数值（17 权重）与实际不符，北极星指标与所有回归基线须按 FSRS-6 重算；原型数值不得作为验收基线。
- 每次调度都新建 `fsrs({...})` 实例（因为 `request_retention` / `maximum_interval` 随 `D` 变化）。实测构造开销可忽略，但需在性能冒烟中确认 P95 ≤ 50 ms（PRD §2.3）。
- `Card.elapsed_days` / `ReviewLog.elapsed_days` / `last_elapsed_days` 在本版已标 `@deprecated`（6.0.0 移除），持久化结构不得依赖它们。
- 升大版本（6.x）必须先用固定 ReviewLog 回放做回归，逐字段比对 `dueAt` / `stability` / `difficulty`，偏差需人工判定是否接受。
